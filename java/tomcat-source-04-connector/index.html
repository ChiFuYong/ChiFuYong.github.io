    Tomcat 源码剖析（四）：连接器启动与线程模型

    chify2026-08-302026-08-30

    Connector 架构

    连接器负责处理网络请求，Tomcat 支持三种协议：

    协议端口用途
    HTTP/1.18080普通 HTTP 请求
    AJP8009与 Apache HTTP Server 集成
    HTTP/28443多路复用（需 SSL）
      graph TD
    A[Connector] --> B[ProtocolHandler]
    B --> C[AbstractProtocol]
    C --> D[Http11Protocol / Http11NioProtocol]
    D --> E[Endpoint]
    E --> F[NioEndpoint]
    F --> G[Acceptor]
    F --> H[Poller]
    F --> I[Executor 线程池]

    Connector 启动

    ProtocolHandler：协议处理器

    NioEndpoint：核心线程模型

    Tomcat 默认使用 NIO（非阻塞 I/O），线程模型如下：

      graph TD
    A[客户端连接] --> B[Acceptor 线程]
    B --> C[Poller 线程 1]
    B --> D[Poller 线程 2]
    C --> E[Worker 线程池]
    D --> E
    E --> F[Servlet 处理]

    三大核心组件

    1. Acceptor（接收连接）

    • 单线程，只负责接收连接
    • 使用 ServerSocketChannel.accept() 阻塞等待

    2. Poller（轮询器）

    • 多个 Poller 线程（默认 2 个）
    • 使用 Selector 轮询就绪的连接
    • 读取数据后交给 Worker 线程池

    3. Worker（工作线程池）

    Worker 线程执行实际的请求处理：

    一个请求的完整流程

      sequenceDiagram
    participant Client
    participant Acceptor
    participant Poller
    participant Worker
    participant Servlet

    Client->>Acceptor: TCP 连接
    Acceptor->>Poller: 注册 Socket
    Client->>Poller: HTTP 请求
    Poller->>Worker: 分发处理
    Worker->>Servlet: 调用 service()
    Servlet->>Worker: 响应数据
    Worker->>Client: HTTP 响应

    线程模型配置

    在 server.xml 中配置：

    参数默认值说明
    maxThreads200Worker 线程池最大线程数
    minSpareThreads10最小空闲线程数
    acceptCount100等待队列长度
    maxConnections10000最大连接数
    connectionTimeout20000ms连接超时时间

    NIO vs NIO2 vs APR

    实现说明适用场景
    NIOJava 原生 NIO默认选择，跨平台
    NIO2Java 7+ NIO.2性能更好
    APRApache Portable Runtime最高性能，需安装

    本篇小结

    1. Connector 通过 ProtocolHandler 处理协议
    2. NioEndpoint 使用 Reactor 模型：Acceptor + Poller + Worker
    3. Acceptor 单线程接收连接
    4. Poller 多线程轮询就绪事件
    5. Worker 线程池执行实际业务逻辑
    6. 配置 maxThreads 等参数可以调优性能

    下一篇我们将分析启动收尾过程和热部署机制。
