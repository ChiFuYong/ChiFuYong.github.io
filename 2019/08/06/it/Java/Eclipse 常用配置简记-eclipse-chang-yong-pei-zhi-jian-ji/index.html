Eclipse 常用配置简记

chify2019-08-062022-04-28

  好记性不如烂笔头，记一篇自己日常使用 Eclipse 的文章，最近也发现 Intellij IDEA很好用，打算换更换 IED，由于公司内部的插件只有 Eclipse 版本的，做项目时还需不时地使用 Eclipse，特此记下一些 Eclipse 的常用习惯，方便日后自己翻阅与查找，快速记起自己的 Eclipse 使用习惯。

一、Eclipse 常用配置顺序

  此处记录一下，本人 Eclipse 工作空间的配置习惯步骤，需要配置的东西如下：

  • jre 运行环境配置
  • Maven 配置（目录和 settings 文件）（${resource_loc}）
  • SVN 或者 Git 配置（Team 设置忽略文件 .classpath、.project、.settings、target等）
  • 关闭不需要的校验（Validation：２[13]５｛１｝[2]３）
  • 设置具体的文字大小（快捷键 Ctrl + or -）
  • WorkSpace 改为 UTF-8
  • 设置代码模板（Code Templates）
  • 打开常用窗口（Package、Navigator、Type Hierarchy、Problems、Search、Console、Progress、 SVN/Git资源库、Servers、Tasks、Histroy），视图（Java、Debug、Synchronize、JRebel）
  • 安装各种所需插件（Subclipse、JRebel、反编译、阿里规约检测、Kite插件、Properties Editor）

  Linux 桌面版下安装就稍微麻烦了一点，记一下出现的小坑

2019年08月09日：　

  • 1. 解决.properties 文件中文显示乱码问题
    Window > General > Content Types > Text > Java Properties File：Default encoing 改为 UTF-8，记得要 update 。修改后，再在 .properties 修改值时就可以显示中文了，但是发现以前的中文内容还是乱码，这里需要安装 Properties Editor 插件。在线安装网址如下：

  • 2. Build Automatically 不自动编译 Maven 工程问题
    工作中突然碰到修改类后不生效的情况，调试半天才发现原来是没重新编译类的问题，稍微测试了一下，20几个 Maven 工程，大致判断有两个工程发生这种情况，没法用 Eclipse 自带的 Project clean 去 clean 项目，并且使用 Maven clean 之后，即使 Build Automatically 开着，也没法自动编译类（src/main/java不行，但是 src/main/resources 却可以，src/test 下的文件都没法编译），谷歌查了一下解决方法，按照所述方法操作没有效果。
    最终自己分析出来原因，应该是 Eclispe 产生的项目文件出问题了，接近30个工程，就只有两个工程有这个毛病，查看了一下这两个工程的 .classpath、.project 文件，发现是因为项目里有人水平略水……用 SVN 之前也没有设置忽略文件，结果合代码的时候把 .classpath 、.project 文件都传到了 SVN 服务器，自己因为换了操作系统，重新拉代码的拉到了这些文件，导致发生了这种诡异的不自动编译问题，从 SVN 库上删除相应文件，重新拉取代码 Maven Update 工程即可。
